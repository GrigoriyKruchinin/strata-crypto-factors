# Гайд для Стадии 1: исследование и paper-trading

Цель Стадии 1: проверить на истории и на живых данных (без реальных денег), приносит ли стратегия доход после всех издержек. Ты ничего не торгуешь и ничем не рискуешь.

> Шаги 1–3 нужны один раз. Разделы 4–7 описывают, как запускать систему.

## 1. Ключи биржи: не нужны

- [ ] Ничего не делай на Binance. В Стадии 1 используются только **публичные данные** (история цен и фандинга, которую Binance бесплатно отдаёт всем).

## 2. Telegram-бот для уведомлений

Бот будет присылать тебе виртуальный портфель (кого «купили», кого «продали в шорт») и итоги дня и недели.

### 2.1. Создай бота
1. [ ] Открой Telegram и найди официального бота **@BotFather** (с синей галочкой).
2. [ ] Отправь ему команду `/newbot`.
3. [ ] Придумай отображаемое имя, например `Strata Alerts`.
4. [ ] Придумай username бота: он должен заканчиваться на `bot`, например `strata_alerts_123_bot`.
5. [ ] BotFather пришлёт **токен** вида `1234567890:AAH...`. Это и есть `TELEGRAM_BOT_TOKEN`.

> ⚠️ Токен работает как пароль: кто его знает, тот управляет ботом. Не публикуй его и не отправляй в чат. Если он утёк, в @BotFather выполни `/revoke` и получи новый.

### 2.2. Узнай свой chat id
`TELEGRAM_CHAT_ID`: номер твоего чата с ботом, чтобы бот знал, кому писать.

1. [ ] Найди своего нового бота по username и нажми **Start** (или отправь ему любое сообщение, например `привет`).
2. [ ] Открой в браузере адрес, подставив свой токен вместо `<TOKEN>`:
   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```
3. [ ] В ответе найди фрагмент `"chat":{"id":123456789,...}`. Число после `"id":` и есть `TELEGRAM_CHAT_ID`.
   - Если ответ пустой (`"result":[]`), ещё раз напиши боту сообщение и обнови страницу.

## 3. Локальное окружение на ноутбуке

### 3.1. Проверь, что установлено
В терминале WSL (Ubuntu) выполни:
```bash
docker --version
docker compose version
uv --version
git --version
```
- [ ] Все четыре команды выводят версию.
  - Если `docker compose` не работает: установи/включи Docker Desktop с интеграцией WSL (Settings → Resources → WSL integration) или Docker Engine внутри WSL.
  - Если нет `uv`: `curl -LsSf https://astral.sh/uv/install.sh | sh`, затем перезапусти терминал.
- [ ] Свободно не меньше **10 ГБ** на диске (история свечей и база данных).

### 3.2. Создай файл `.env`
`.env`: файл с настройками и секретами, который хранится только у тебя на компьютере и никогда не попадает в git.

1. [ ] В папке проекта выполни:
   ```bash
   cp .env.example .env
   ```
2. [ ] Открой `.env` в редакторе и заполни:
   ```
   DB_PASSWORD=<придумай-длинный-пароль>
   TELEGRAM_BOT_TOKEN=<токен-от-BotFather>
   TELEGRAM_CHAT_ID=<твой-chat-id>
   ```
3. [ ] `EXCHANGE_API_KEY` и `EXCHANGE_API_SECRET` **оставь пустыми**.
4. [ ] Проверь, что git не видит файл: `git status` не должен показывать `.env`.

> ⚠️ Если `git status` показывает `.env`, остановись и напиши об этом Claude: файл не должен попасть в репозиторий.

После шагов 1–3 напиши в чат: **«Start Implementation»**.

## 4. Скачивание истории

```bash
uv sync
make download-history
```
- [ ] В конце в терминале строка `symbols=... failed=0`.

Скачиваются дневные свечи и история фандинга по всем фьючерсам Binance с 2020 года, **включая монеты, которые уже сняты с торгов** (иначе результат был бы приукрашен). Первый запуск занимает 1–2 часа, повторные идут быстро: уже скачанное берётся из папки `data/`. Если загрузка оборвалась, просто запусти команду ещё раз.

Отчёт о качестве данных (пропуски, «пустые» дни) лежит в `data/quality_report.json`.

## 5. Исследование (бэктест)

Бэктест: проверка стратегии на прошлых данных, как будто она торговала тогда. Исследование идёт по заранее зафиксированному плану (`docs/research/protocol.md`), по шагам:

```bash
make research STEP=train        # 18 вариантов на периоде подбора 2020–2023
make research STEP=robustness   # проверки финалистов: 1000 случайных сигналов и др. (~30 мин)
make research STEP=freeze       # фиксирует выбранную стратегию, менять её дальше нельзя
make research STEP=holdout      # один раз: проверка на 2024 – сейчас
```
- Результаты: `docs/research/results/*.json`, журнал всех прогонов: `docs/research/experiment-log.jsonl`.
- ⚠️ Шаг `holdout` можно выполнить **только один раз**. Повторный запуск программа запретит: контрольный период после просмотра «сгорает».

## 6. Запуск локального стека и paper-trading

Стек: набор сервисов в Docker (база данных PostgreSQL, очередь Redis, фоновые обработчики), которые работают вместе. Paper-trading: стратегия работает на живых данных, но сделки виртуальные, деньги не тратятся.

Нужен шаг `freeze` из раздела 5: paper-trader торгует именно выбранную там стратегию.

```bash
docker compose -f docker-compose.local.yml up -d --build
docker compose -f docker-compose.local.yml ps
```
- [ ] У всех сервисов статус `healthy`, у `migrations` статус `Exited (0)` (это нормально: он один раз готовит базу и выключается).
- Каждый день в 00:15 UTC (21:15 по времени UTC−3) система обновляет данные, ведёт виртуальный счёт и присылает итоги дня в Telegram. По понедельникам приходит новый портфель, итоги недели и сверка с бэктестом.
- [ ] Ноутбук и Docker должны быть включены в это время. Если ноутбук был выключен, пропущенные дни догонятся при следующем запуске, но ребалансировка выполнится с опозданием (в сообщении будет предупреждение).
- [ ] Нужно минимум **28 дней** работы, чтобы сравнить живой результат с бэктестом.

Остановить: `docker compose -f docker-compose.local.yml down` (данные в базе сохраняются).

## 8. Как читать отчёт Go / No-Go

Итоговый отчёт: `docs/reports/stage-1-go-no-go.md`. Главные показатели:

| Показатель | Что значит | Порог |
|---|---|---|
| **Плюс к депозиту** (обязательно) | Средняя чистая доходность в месяц на периоде, который не участвовал в подборе, после всех издержек. Без плюса Go невозможен | > 0%, ориентир 1,5% в месяц, итог обсуждаем |
| Годовая доходность (чистая) | Сколько процентов в год после всех комиссий и фандинга | ≥ 20% |
| Максимальная просадка | Самое глубокое падение счёта от пика | ≤ 25% |
| Sharpe | Доход на единицу риска: чем выше, тем стабильнее рост | ≥ 1.0 |
| Издержки ×2 | Что будет, если комиссии и проскальзывание окажутся вдвое больше | Sharpe ≥ 0.5 |
| Случайные сигналы | Лучше ли стратегия, чем «подбрасывание монетки» с тем же портфелем | лучше 95% случайных |
| Зависимость от монет | Не держится ли весь доход на 1–2 удачных монетах | ни одна > 15% прибыли |
| Скользящие окна | Доля полугодий, где стратегия была в плюсе | ≥ 60% |
| Paper vs бэктест | Совпадает ли живая симуляция с расчётом на тех же днях | расхождение ≤ 25% |

В конце отчёта есть блок **«Простыми словами»**: короткий вывод, стоит ли рисковать деньгами и почему.

> ⚠️ Все результаты исторические или симуляционные. Это не прогноз и не гарантия дохода.
